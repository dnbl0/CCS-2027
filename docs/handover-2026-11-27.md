## How work is done here

- Repo `dnbl0/CCS-2027` (public; Actions budget $0, so avoid wasted CI runs). Rails 8.1 + Blacklight 9 app in `ead-ccs-test/`,
  Ruby **4.0.10** (`rbenv install 4.0.10`).
- One small change per branch, in its own worktree under `~/CCS-2027-worktrees/` (never in the shared checkout
  `~/CCS-2027`, which is stale and has the owner's uncommitted files). Any descriptive prefix (`fix/`, `docs/`, `chore/`,
  `design/`, `refactor/`): `auto-merge.yml` is gone, nothing merges without CI.
- Before pushing, from `ead-ccs-test/` with `DB_SUFFIX=_<branch>`: `bin/rails db:prepare`;
  `SOLR_URL=http://127.0.0.1:1/solr/blacklight-core bin/rails test` (as CI's rails job); `bin/rubocop`;
  `bundle exec erb_lint --lint-all`; `bin/brakeman --quiet --no-pager --exit-on-warn --exit-on-error`; `ruby script/check_docs.rb`;
  `ruby script/i18n_check.rb`. A 2026 prototype change also needs `npm test` at the root (symlink `node_modules` from
  `~/CCS-2027/node_modules`, then remove the link).
- **Local Solr data differs from CI's**: about 20 Solr-backed tests (ids like `emu-9044`, featured records, free reuse) fail
  locally on `main` too. Trust CI for those. Since #94 the `system` job runs `bin/rails test` against an indexed core, so every
  `needs_solr` test runs in CI now.
- Open a PR (`gh pr create --repo dnbl0/CCS-2027 --base main`), wait for `rails` and `system` (and `test` when root files change)
  to pass **on the latest commit**, then `gh pr merge N --repo dnbl0/CCS-2027 --merge`. Merge `origin/main` into an older branch
  before merging it. Timing-sensitive tests (health, colour extractor, debias performance) can fail when the laptop is busy:
  rerun them alone before treating them as real.
- Commits end with the `Co-Authored-By` and `Claude-Session` lines from the session's system reminder; PR bodies end with the
  "Generated with Claude Code" line.
- In zsh, a file list in a variable is **one word**: use an array (`F=(a b); cmd "${F[@]}"`) or `xargs`.
